完整启动流程：

  Set-Location D:\project\loveapp

  # Docker 未运行时启动 Docker Desktop
  Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"

  # 启动 Qdrant
  docker compose up -d

  # 启动 LoveApp
  uv run loveapp chat  --user-id local-user --relationship-id partner-24  --debug-memory  --stream --timings

  另开一个终端实时查看记忆：

  Set-Location D:\project\loveapp

  uv run loveapp memory watch  --user-id local-user --relationship-id partner-23

  退出聊天输入 /quit。停止 Qdrant 使用：

  docker compose stop




第一次 git push -u origin main 成功后，后续同步使用以下流程：

  cd D:\project\loveapp

  # 1. 查看修改
  git status
  git diff

  # 2. 运行测试
  uv run pytest

  # 3. 暂存全部修改
  git add -A

  # 4. 检查即将提交的内容
  git diff --cached

  # 5. 创建提交
  git commit -m "feat: add conversation summary support"

  # 6. 推送到 GitHub
  git push

  提交信息可以按类型编写：

  feat: 新增功能
  fix: 修复问题
  refactor: 重构但不改变功能
  test: 增加测试
  docs: 修改文档
  chore: 配置或依赖调整

  例如：

  git commit -m "fix: prevent date planning route misclassification"
  git commit -m "feat: add episodic memory summaries"
  git commit -m "docs: update LoveApp interview guide"

  如果 git push 提示远程存在本地没有的提交，先执行：

  git pull --rebase origin main
  git push

  不要使用 git push --force，除非明确知道要覆盖远程历史。

  日常可以记成：

  修改代码 → 测试 → git add -A → git commit → git push

  GitHub Connector 读取的是远程仓库，因此只有执行 git push 后，GPT 才可能看到新版本；本地未提交或未推送的修改不会同步。
